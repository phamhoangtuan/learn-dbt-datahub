## Project Overview

An end-to-end data engineering learning pipeline implementing **Medallion Architecture** (Bronze → Silver → Gold) and **Clean Architecture** principles using simulated banking data.

**Stack**: Python 3.10 · uv · dbt-snowflake 1.9.4 · Snowflake Emulator (DuckDB-backed) · DataHub · Faker · Polars

## Commands

### Environment Setup
```bash
make setup          # Install deps + start Snowflake Emulator
make datahub-up     # Start DataHub separately (takes ~60s, UI at localhost:9002)
```

### Infrastructure
```bash
make infra-up       # Start Snowflake Emulator (localhost:8080)
make infra-down     # Stop Snowflake Emulator
make infra-logs     # Tail emulator logs
```

### Pipeline (Phase 2+)
```bash
make generate       # Generate synthetic banking events → data/landing_zone/
make load           # Load JSONL into Snowflake Emulator Bronze layer
make transform      # Run dbt build (all Bronze/Silver/Gold models)
```

### dbt (from dbt_project/)
```bash
uv run dbt debug --profiles-dir .                # Verify connection
uv run dbt run --profiles-dir . -s bronze        # Run single layer
uv run dbt test --profiles-dir .                 # Run all tests
uv run dbt docs generate --profiles-dir . && uv run dbt docs serve --profiles-dir .
```

### Verification
```bash
make dbt-debug      # dbt → emulator connection check
uv run python -c "import snowflake.connector; import datahub; import faker; import polars"
```

## Architecture

### Data Flow
```
scripts/generate_events.py   (calls ingestion/generator.py)
  → data/landing_zone/{accounts,transactions}.jsonl
    → scripts/load_to_emulator.py  (calls ingestion/loader.py)
      → BANK_DB.RAW.{ACCOUNTS_RAW,TRANSACTIONS_RAW}  ← Bronze (VARIANT columns)
        → dbt silver models (parsed, typed, deduplicated)
          → dbt gold models (aggregates, dimensional models)
```

### Directory Structure
```
ingestion/          # Python package: reusable generator & loader logic
scripts/            # Thin CLI wrappers that call ingestion/
dbt_project/        # dbt project (profiles.yml checked in, pass --profiles-dir .)
  models/bronze/    # Raw VARIANT table selects
  models/silver/    # Parsed, cast, deduplicated entities
  models/gold/      # Business aggregates & star schema
  macros/           # Business rules (Clean Architecture: Entities layer)
infrastructure/     # Docker Compose for Snowflake Emulator
data/landing_zone/  # JSONL files (gitignored, generated by make generate)
tests/              # Python unit/integration tests (Phase 2+)
```

### Clean Architecture Mapping
- **Entities (inner)**: Business rules as dbt macros (e.g., `is_suspicious_transaction`)
- **Use Cases (middle)**: dbt models that execute transformations
- **Adapters (outer)**: `stg_*` staging models normalize JSON in; Gold models serve BI out

## Key Implementation Notes

- All Python/dbt commands use **`uv run`** — never activate `.venv` manually
- **Python 3.10** is required — snowflake-connector-python auth fails on 3.13 with the emulator
- **dbt-snowflake pinned to `>=1.9.4,<1.10.0`** — 1.10+ requires connector 4.x which the emulator rejects
- **Snowflake proxy sidecar** (`infrastructure/snowflake_proxy.py`): sits on port 8080 in front of the emulator. Fixes connector 3.x ↔ emulator bugs: (1) decompresses gzip bodies, (2) injects session params with correct Python types, (3) synthesises `rowtype`/`rowset` for DDL responses (emulator returns `rowtype: []` without `rowset`, causing `len(None)` in connector). Restarts with `make infra-down && make infra-up`.
- The emulator uses `protocol: http` — dbt and the connector must not enforce TLS
- **Emulator type limitations**: Bronze tables use `TEXT` (not `VARIANT`) — DuckDB backend doesn't support Snowflake's `VARIANT`, `OBJECT`, or `JSONB` types. JSON data stored as text strings.
- **Emulator SQL limitations**: no `CREATE DATABASE`, no three-part names (`DB.SCHEMA.TABLE`), no `PARSE_JSON()`, no explicit `COMMIT`. Use unqualified table names (session context is `BANK_DB.RAW`). Use `INSERT INTO t (col) VALUES ('...')` for JSON rows.
- `load_to_emulator.py` uses `INSERT INTO table (data) VALUES ('json_string')` — emulator lacks COPY/stage/PARSE_JSON support
- Silver models (Phase 4) must use DuckDB JSON extraction syntax (`data->>'field'` or `json_extract_string(data, '$.field')`) instead of Snowflake's `data:field::type`
- `dbt_project/profiles.yml` is checked in; always pass `--profiles-dir .` from inside `dbt_project/`
- DataHub is started separately via `make datahub-up` (`datahub docker quickstart`), not in docker-compose.yml
- **Rancher Desktop socket**: The host uses Rancher Desktop; Docker socket is at `~/.rd/docker.sock` (not `/var/run/docker.sock`). All `datahub` CLI calls in the Makefile set `DOCKER_HOST=unix://$(HOME)/.rd/docker.sock` to fix Python docker SDK detection.
- Use **Polars** (not pandas) for all DataFrame operations: `import polars as pl`
